## Goals

1. Make the site noticeably faster (better LCP, lower JS/image weight, fewer reflows).
2. Confirm `sitemap.xml` is valid and ready to submit at `https://livingwitharthritis.org.uk/sitemap.xml` in Google Search Console.

## Part 1 — Sitemap verification

Current state (already in good shape):
- Auto-generated by `scripts/generate-sitemap.ts` on `predev`/`prebuild`.
- 449 URLs, all under `https://livingwitharthritis.org.uk/`.
- Excludes `/auth`, `/admin/*`, `/chat`, `/donation-result`, `/unsubscribe`, `/newsletter/confirm`, `/site-index` — these match `robots.txt` Disallow rules (no "indexed though blocked by robots" warnings).
- `robots.txt` ends with `Sitemap: https://livingwitharthritis.org.uk/sitemap.xml`.

Actions:
- Re-run the generator to refresh `lastmod` and pick up any new routes.
- Validate the XML (well-formed, `<urlset>` namespace correct, no duplicate `<loc>`, no URLs that are also `Disallow`ed).
- Output a one-line "ready to submit" confirmation with the exact URL to paste in GSC: `https://livingwitharthritis.org.uk/sitemap.xml`.

No structural changes unless validation surfaces an issue.

## Part 2 — Performance improvements

Audit findings:
- Route-level code splitting is already in place (every page is `lazy()`), and non-critical widgets (chat, cookie banner, accessibility toolbar, exit-intent, etc.) are also lazy. Good baseline.
- `public/openverse/` is **8.9 MB** of JPGs and `public/images/` is **2 MB** — these are the biggest LCP/data drag.
- `public/exercise-videos/` is **71 MB** of MP4s self-hosted.
- Google Fonts loaded as 3 families with many weights; preconnect + `display=swap` already used but weight count is heavy.
- No `width`/`height` on many remote-ish images → CLS risk.

Changes:

1. **Images — convert and serve modern formats**
   - Add `vite-imagetools` and convert imports in `src/assets/*` to emit AVIF + WebP variants with `<picture>` fallback for hero/featured images.
   - For files in `public/openverse/` and `public/images/` (served as-is), run a one-shot `sharp` script to write `.webp` siblings (quality ~75) and update components to reference the `.webp` with `<picture><source type="image/webp">…<img src="…jpg">`. Keeps JPG as fallback, no broken links.
   - Add explicit `width`, `height`, and `loading="lazy"` + `decoding="async"` to non-LCP images; LCP hero stays eager with `fetchpriority="high"`.

2. **Videos — stop shipping 71 MB on demand**
   - Set `preload="none"` and `poster="…"` on all `<video>` tags so MP4 bytes only download on play.
   - Add `playsInline` and lazy-mount the `ExerciseVideo`/`ExerciseVideoModal` only when the user opens the modal (already a modal — verify the `<source>` isn't in the DOM until open).

3. **Fonts — trim weight matrix**
   - Drop unused weights (keep Plus Jakarta 400/600/700, Playfair 700, DM Sans 400/500). Reduces font CSS payload and competing preloads.
   - Add `&text=` subsetting only if Playfair is used in a small number of headlines (optional; skip if it complicates things).

4. **JS — squeeze remaining bytes**
   - Verify `framer-motion` is not pulled into the homepage chunk (it's intentionally excluded from `manualChunks` — confirm via build output). If anything on `Index` imports it eagerly, swap to CSS transition.
   - Add `<link rel="dns-prefetch">` / `preconnect` for the Supabase URL (already used on first page interaction).
   - Remove the `optimizeDeps.include` for `react-i18next` / `i18next` if the project doesn't actually use them (quick `rg` check; if unused, drop to shrink the pre-bundle).

5. **Caching**
   - In `public/_headers`, ensure hashed `/assets/*` get `Cache-Control: public, max-age=31536000, immutable` and `*.jpg|webp|avif|mp4` get long-cache too. (Verify current rules; add if missing.)

6. **Verify**
   - Run the production build and inspect `dist/` chunk sizes; confirm homepage initial JS is unchanged or smaller and that openverse JPGs have webp siblings.
   - Use the browser performance profile tool to capture LCP before/after on `/`.

## Out of scope

- No content rewrites, no route changes, no design changes.
- No migration to a CDN image transformer (would need user decision on Cloudflare/etc.).
- No removal of MP4s (kept, just lazy-loaded).
