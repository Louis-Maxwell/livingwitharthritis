# Delivery roadmap



### Days 1–7: quick wins

- SEO exports current indexing reasons and page/query performance with dates; records five soft-404 examples for developer reproduction (R01–05).
- Welfare reviewer corrects PIP fluctuation and related-benefit claims; clinician/pharmacist schedules high-risk content review (R07/R12).
- Developer reviews/deploys sitemap PR #130 and tests live XML, statuses and route eligibility (R10).
- GA4 consultant stops treating clicks/mailto/query-string success as verified outcomes; documents existing counts before changing definitions (R08/R28).
- SEO/content updates the first eight accurate snippets and adds relevant links to five key pages (R09/R11).
- Assign report/alert owners and record a stable baseline; no unsubstantiated growth promises (R06/R26).

### By day 30: foundations

- Complete indexing triage, rendered crawl/orphan candidates, canonical decisions and initial template fixes (R01–05/R14/R17/R23).
- Confirm real newsletter/contact success; reconcile GoFundMe handoffs and income; implement privacy-safe event dictionary and dashboards (R15/16/26–28/44).
- Baseline mobile performance; fix measurable layout/image/script issues; perform accessibility task testing (R18–22/R32/33).
- Review clinical/welfare pages receiving the most impressions; publish credible reviewer and governance records (R07/12/25).
- Assign ten pillars and validate candidate keyword intent/demand. Resolve overlap before briefing new pages (R24/35/37).
- Verify schema, product/video issues and AI/bot measurement settings using actual live tests (R29–31/R38/39).

### By day 90: growth platform

- Priority templates deliver consistent useful initial and rendered content; monitor recrawl/indexing outcomes (R01/14).
- Ten pillars are refreshed or clearly mapped, with focused spokes and original reviewed assets (R35/36).
- Confirmed signup/contact/donation reporting is reliable, with documented limitations for external fundraising (R08/15–16/27).
- Accessibility/performance improvements are measured rather than assumed; field data monitored if available (R18–22/33).
- Begin legitimate partner distribution and community co-design; iterate CTAs from reliable evidence (R34/40–42).

### KPI and evaluation framework

Use rolling 28-day and 90-day comparisons, with matched countries/devices/query intent and year-on-year context when available. Keep a release log. Do not set a universal target of “index every URL”: intentional duplicates, redirects and utilities should stay excluded.

| Outcome | Baseline | Success measure |
| --- | --- | --- |
| Organic search | 336 clicks / 32,283 impressions over observed 3 months | Growth in relevant non-brand clicks with accurate stable cohorts; leadership sets target after 30-day repair baseline |
| CTR | 1.04% overall; page metrics above | Improved CTR for priority query groups at comparable positions; avoid one headline aggregate |
| Indexing quality | 50 soft 404s; 426 discovered; 93 crawled unindexed, report lag | Priority useful pages correctly rendered/indexed; reduction in verified accidental exclusions |
| Sitemap | 1,004 in one inventory | Four processed sections with valid canonical/status eligibility |
| CWV | No GSC field data | Valid p75 measurements; target good thresholds where samples support judgement |
| Newsletter / contact | No recent configured outcome-event data | Confirmed counts reconciled to actual service/provider records |
| Donations | Click/checkout key events; external provider | Verified fundraising totals; honest attribution limits |
| Engagement | Existing many timers/clicks | Meaningful resource/video/onward-task use and returning readers |
| AI visibility | 6.72K rounded impressions, 236 pages | Accurate cited priority sources and trend in dedicated report; no conflation with clicks |
| Accessibility | Sampled observations only | Critical journeys pass keyboard/screen-reader tests and tracked issues resolved |
