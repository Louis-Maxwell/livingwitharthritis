# Living With Arthritis — Unified Blog Editorial and Publishing Standard

Status: Implementation plan (not a claim that articles have been updated)
Baseline: 16 October 2026, main branch generated catalogue: 692 published entries, 670 marked pending review, 28 categories. Recalculate counts before each rollout.

## 1. Reference pattern

Based on the user-provided `vitamin_d_autism_blog (1).zip`: introduction, four illustrative image placements, explanatory H2 sections, balanced evidence discussion, practical guidance, UK-specific advice, FAQs, conclusion, numbered references, and medical disclaimer. Its SVGs are **placeholders**, not publication-ready licensed photographs.

Apply consistent presentation without flattening condition-specific clinical nuance. Retain useful existing material, headings and working URLs. Do not mechanically rewrite established advice or claim clinical approval.

## 2. Required article contract

- Unique slug and canonical URL; maintain redirects if a URL must change.
- H1/title, concise accurate direct answer, non-misleading meta title/description, descriptive excerpt, relevant keywords and category.
- Clear publication date, updated date, named author when known, verifiable reviewer credentials and actual review date **only when review occurred**.
- Main content: introduction; what the topic means; evidence and uncertainty; signs/management/risks as applicable; UK/NHS/NICE guidance where relevant; actionable steps; 3–5 genuinely useful FAQs; conclusion.
- 3–4 *distinct* meaningful images per article (one cover plus 2–3 body images), rights provenance, descriptive non-keyword-stuffed alt text, intrinsic dimensions, responsive sizing and lazy loading for below-fold images. Decorative images may have empty alt. Never reuse the same image across dozens of articles.
- Evidence: claim-to-source map for medical claims; citations close to claims and a reference list with publisher, title, URL, and access/check date. Use current NICE/NHS/SIGN/BNF guidance, systematic reviews and primary studies as appropriate. Distinguish association from causation; do not imply a reference verifies claims it does not cover.
- Medical disclaimer tailored to the article; clear red flags and emergency escalation when relevant, not generic reassurance.
- Original language and licensed media; attribution and source audit.
- Downloadable accessible PDF/print experience only after ensuring it includes citations, alt-text equivalents, and current version/date.
- Structured data: valid BlogPosting/Article JSON-LD, FAQPage only if appropriate and consistent with visible content; breadcrumbs and canonical metadata.
- Editorial review must be real: pending content remains pending until a qualified reviewer signs off; avoid unverified 'reviewed daily' claims.

## 3. Repo integration

Source of truth: `src/content/blog/posts/<slug>.json`, validated by `src/lib/blog/schema.ts`.
Catalogue and derived metadata are generated by `scripts/generate-blog-catalog.ts`; do not manually edit `src/content/blog/catalog.generated.json` or other generated artefacts.
Current schema already has optional `citations`, `cover`, and `content`; design a backward-compatible structured `article_images` or separate image manifest, with required `src`, `alt`, `credit`, `licence`, `width`, `height`, and placement. Migrate legacy posts incrementally.
The cover generator enforces unique files under `public/openverse/`. Keep that invariant.
Prefer reusable React components for article images, reference list, disclaimer, reviewer information and downloads, rather than duplicating markup.
Use responsive images, explicit sizes, defer non-critical images, ensure WCAG 2.2 AA keyboard/focus/contrast and reduced-motion support.

## 4. Phased rollout

0. Baseline and freeze: export ordered slug inventory from current catalogue; flag missing citations, unsupported claims, absent review dates, weak alt text, duplicates, outdated sources, image rights, broken links and thin FAQs. Assign priority based on medical risk and traffic, not only catalogue order.
1. Prototype: convert 5 varied articles (one frailty, one inflammatory, one medication, one benefits, one lifestyle) and validate rendering, indexing, performance, accessibility and editorial workflow.
2. First 50 (catalogue positions 1–50): complete source mapping and 3–4 licensed images; preserve prior branch work only after diff review.
3. Second 50 (51–100): reconcile draft PR #216; do not treat topic-level citation additions as claim verification.
4. Remaining catalogue: batches 101–150, 151–200, 201–250, 251–300, 301–350, 351–400, 401–450, 451–500, 501–550, 551–600, 601–650, 651–692.
5. Continuous editorial maintenance: recheck high-risk medical pages when NICE/NHS guidance changes, update citations and reviewed dates only after real review.

Each batch: inventory -> evidence matrix -> preserve/revise -> images and rights -> SEO/structured data -> clinical/editorial review -> automated checks -> draft PR -> reviewer approval -> merge -> monitor Search Console and Core Web Vitals.

## 5. CI release gates

Fail batch PRs on invalid schema, duplicate slugs/titles/covers, missing image files, broken internal links, malformed reference URLs, missing alt/rights metadata, absent required sections, bad canonicals, and inaccessible components. Warn (manual review) for unsupported clinical claims, plagiarism risk, image relevance and source quality.
Run existing `bun scripts/generate-blog-catalog.ts --check`, `bun run seo:blog-guards`, typecheck, lint, tests and build as applicable; regenerate derived files when required.
Clinical sign-off is mandatory before describing content as medically reviewed. No bypass of required checks.

## 6. Definition of done per article

- Original, accurate, useful article; all consequential medical statements checked against relevant credible sources and uncertainty explained.
- 3–4 licensed original/relevant images, descriptive alt, credit/licence and working assets.
- Working numbered inline citations and reference section; no citation merely attached to a topic.
- Relevant FAQs, conclusion, UK advice, tailored disclaimer and accurate review metadata.
- SEO fields, canonical, schema, accessible responsive layout and working download/print.
- Passes automated validation plus human editorial/clinical approval; no invented clinical review.

## 7. Tracking and reporting

Maintain a CSV/JSON migration manifest keyed by slug: batch, owner, status (unstarted/in-progress/evidence-check/image-rights/clinical-review/approved/merged), citation count, claim checks, image count, licence verification, last reviewed, PR, deployed URL and validation failures.
Report exact completed/remaining counts after each merged PR. Never label a batch completed when only a branch or PR exists.

## 8. Risks

Medical misinformation (YMYL), unsupported medication advice, licensing and copyright, AI-generated clinical overconfidence, broken blog URLs, performance regression from 3–4 images, inaccurate reviewer attribution, and false claims about clinical approval. Use staged rollouts, human approval, unique media, conservative language and rollback-ready PRs.
